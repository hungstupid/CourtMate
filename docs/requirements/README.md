# Requirements — all phases

Keep the **living product requirements** for CourtMate here. Start with PA0/PA1 concept and stakeholders; expand in PA2 and maintain approved changes through PA5.

Typical deliverables: product vision, stakeholder and user profiles, MoSCoW scope, constraints, functional requirements (FR IDs), measurable nonfunctional requirements (NFR IDs), domain rules, use-case diagrams/specifications, low-fidelity prototypes, acceptance criteria, a traceability matrix and review findings.

**When to update:** whenever agreed business rules change, including booking duration, owner approval vs automatic confirmation, cancellation eligibility, availability boundaries or role permissions. Label proposed rules as **unconfirmed** until team/TA decision. PA0 did **not** fix a 60-minute booking duration.

**Rule:** every Must-have requirement needs a verifiable acceptance criterion and corresponding PA4 test coverage. Keep baseline changes documented; finalized PA2 snapshot is in `pa/PA2/`, not this folder.
